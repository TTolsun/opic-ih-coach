# 말하기 평가와 피드백 타당성 검증

검증 대상은 [이슈 #40](https://github.com/TTolsun/opic-ih-coach/issues/40)과 앱 코드 `293ae5df3671f03c753e28c73422b48060eab287`입니다. 2026년 11월 12일에 한국 표준시를 기준으로 자료를 확인했습니다.

직접 입력이 발화 준비도에 들어가고, 필수 항목이 없는 AI 응답이 0점으로 처리되는 문제를 우선 수정합니다. 학습에 사용할 관찰은 질문의 과업 완수, 전달된 내용, 문장 사이의 실제 관계, 과업에 필요한 시간대의 유지입니다.

## 사전 검토 기준

질문과 전사를 먼저 읽고 각 항목에 해당하는 근거 구절을 기록합니다. 평가 점수와 피드백은 기대 관찰을 기록한 뒤 확인합니다. 녹음이 있으면 전사보다 녹음을 먼저 듣고, 인식기가 바꾼 말과 실제로 발화한 말을 구분합니다.

| 항목 | 검토 기준 |
| --- | --- |
| 질문 적합성 | 질문이나 실제 연습 미션이 요구한 대상과 과업을 확인합니다. 해당 과업을 완수했는지, 일부만 답했는지, 다른 과업을 수행했는지 기록합니다. 질문을 따라 읽은 경우에는 수행 근거가 없습니다. |
| 내용 전달 | 청자가 답의 요점과 그것을 뒷받침하는 사실을 복원할 수 있는지 확인합니다. 구체적 내용, 누락된 요구 사항, 이해를 방해한 구절을 적습니다. 문항을 완수한 짧은 답도 인정합니다. |
| 문단 연결 | 원인과 결과, 시간 순서, 대조, 지시 대상이 앞뒤 문장에서 이어지는지 봅니다. 연결어를 덧붙인 경우 실제로 뜻의 관계가 명확해졌는지 확인합니다. |
| 시간대 유지 | 과업에서 필요한 시간대를 먼저 정하고, 각 절의 사건과 시간 표현이 맞는지 확인합니다. 인용, 현재 상태 설명, 의도적인 시간 전환과 스스로 고친 표현을 따로 기록합니다. |
| 발화와 피드백 | 반복, 중단, 자기 수정의 위치와 전달에 미친 영향을 적습니다. 피드백은 전사나 녹음에 근거하는지, 가장 중요한 문제를 먼저 다루는지, 같은 질문에서 실행할 수 있는지 확인합니다. |

독립 수동 검토에는 검토자 역할과 자격, 음성 청취 여부, 모델 보조 여부를 기록합니다. 두 검토자가 독립적으로 검토할 수 있으면 불일치 구절을 남기고 합의합니다. 통제 사례의 기대 관찰은 Codex가 작성한 사례 설계상의 판정이며, 사람의 청취나 등급 판정은 별도 근거가 필요합니다.

ACTFL의 2024년 말하기 지침은 기능과 과업, 정확성, 맥락과 내용, 담화 유형(FACT)을 함께 살핍니다. IH 기술은 적절한 주요 시간대에서 서술과 묘사, 연결된 문단 수준 담화를 자주 수행할 수 있으나 지속하는 데 어려움이 생길 수 있다고 설명합니다. Advanced Low 기술에는 시간대별 서술과 묘사가 따로 이루어질 수 있고, 예상 밖 상황을 처리하거나 의사소통을 복구하는 능력이 포함됩니다. 이를 바탕으로 이 검증은 시간대 전환이 필요한 과업을 자료에 포함하고 각 문항에서 요구한 시간대의 유지 여부를 봅니다. 앱의 단어 수와 점수는 이 지침으로 환산할 수 없습니다. [ACTFL 지침 개요](https://www.actfl.org/proficiency-guidelines-overview) · [ACTFL Proficiency Guidelines 2024, Speaking, 인쇄면 12·18·20쪽](https://www.actfl.org/uploads/files/general/Resources-Publications/ACTFL_Proficiency_Guidelines_2024.pdf)

## 통제 사례의 기대 관찰

질문과 영어 전사는 [재현용 JVM 테스트](../app/src/test/java/com/opicih/coach/EvaluationValidityProbeTest.kt)에 있습니다. 합성 전사에는 실제 학습자 정보가 없습니다. 음향 수치를 함께 준 경우에도 파형에서 얻은 수치가 아니라 실험에서 고정한 입력입니다.

| 비교 | 실행 전 기대 관찰 |
| --- | --- |
| A와 B | 짧은 A는 도서관에서 있었던 일과 결과를 직접 전달합니다. 길고 잘 이어진 B는 요리 수업 이야기로, 도서관 질문의 과업을 수행하지 못합니다. B의 질문 적합성을 더 낮게 평가해야 합니다. |
| C와 C+ | C는 여러 사실을 나열합니다. C+는 같은 사실에 연결어를 붙이지만 도서관에서 무슨 일이 어떻게 해결됐는지 설명하는 인과관계를 추가하지 않습니다. 문단 연결이 개선되었다고 단정할 근거가 없습니다. |
| D와 D+ | D는 도서관의 문제, 대처, 결과를 과거 시제로 연결합니다. D+의 자전거 구매 계획은 과업에 기여하지 않습니다. D에는 미래 문장 추가를 권할 이유가 없습니다. |
| D와 D-Q | 같은 전사를 도서관 경험 질문과 병원 경험 질문에 각각 답하게 합니다. 내용과 문장 구조는 같고 질문 적합성만 달라집니다. |
| E와 E-clean | E에서 화자는 `go`를 `went`로 스스로 고칩니다. `I see`는 과거 맥락에서 고치지 않은 오류입니다. 앞에 필러와 인접 반복, 뒤에 중단 한 건이 있습니다. 보정한 E-clean의 전사만으로는 원래 발화의 오류와 중단 횟수를 확정할 수 없습니다. |
| F와 F+ | F의 둘째 문장에 명시적 시간 표지가 없어도 도서관 이야기의 과거 맥락이 이어집니다. F+는 해당 절을 과거형으로 고친 합성 재답변입니다. |
| G와 H | G는 현재의 두 장소를 비교하므로 과거 시제가 필요 없습니다. H는 과거 문항을 미래 계획으로 바꾸라는 명시적 미션에 답하므로 미래 시간대가 필요합니다. |

## 평가와 집계 경로

1. **말하기 화면에서 캡처합니다.** `SpeakingViewModel`은 `CapturePolicy`로 캡처를 선택하고 `AnswerCapture.stop`에서 전사와 음향 정보를 받습니다. 자유 발화·모의시험·틀 붙이기·문단 사다리는 녹음 전사 설정, 음성 전송 동의, Gemini 키가 모두 있을 때 녹음과 원문 전사를 선택합니다. 기기 STT는 인식기 RMS와 전사를, 녹음은 PCM RMS와 선택적 전사를 사용합니다. 처음부터 직접 입력하거나 인식 실패 뒤 직접 입력하면 `submitTyped`가 음향과 오디오 경로가 없는 `TYPED`를 저장합니다. [CapturePolicy](../app/src/main/java/com/opicih/coach/learning/CapturePolicy.kt) · [AnswerCapture](../app/src/main/java/com/opicih/coach/speech/AnswerCapture.kt) · [SpeakingViewModel](../app/src/main/java/com/opicih/coach/ui/screens/SpeakingViewModel.kt)
2. **로컬 평가를 계산하고 조건에 따라 AI 평가를 적용합니다.** `PracticeRepository.analyzeAndSave`는 전사 태그를 제외한 텍스트로 담화 지표를 계산합니다. 텍스트가 없는 녹음은 음향만 분석합니다. `AppContainer.realAi`는 AI 사용 설정, 텍스트 전송 동의, 키를 확인합니다. 전사에 5단어 이상 있으면 Gemini에 질문, 미션, 원래 전사와 지표를 보냅니다. AI 성공 시 AI 피드백과 점수를 쓰면서 로컬 측정 한계와 오류 항목을 합칩니다. 실패 시 로컬 결과를 저장합니다. `BLIND` 등 암기 모드만 AI에 목표 스크립트를 보냅니다. 모의시험 문항과 SAIL 대화의 개별 턴은 로컬로 평가합니다. SAIL 추가 질문과 종합 피드백에는 선택적으로 Gemini를 사용합니다. [AppContainer](../app/src/main/java/com/opicih/coach/App.kt) · [PracticeRepository](../app/src/main/java/com/opicih/coach/data/repo/Repositories.kt) · [MockScreen](../app/src/main/java/com/opicih/coach/ui/screens/MockScreen.kt) · [SailConversationViewModel](../app/src/main/java/com/opicih/coach/ui/screens/SailConversationViewModel.kt)
3. **시도, 피드백, 관측치를 저장하고 집계합니다.** Room의 시도 기록에 `captureMode`, `feedbackSource`, `score`, `metricsJson`, `feedbackJson`을 저장합니다. 오류 노트에는 피드백의 `errors`를 누적합니다. 기록 화면의 오류 추세는 원문 전사 플래그가 있는 시도를 사용합니다. 다음 OPIc 조건은 최근 시험 이후 시도 중 `READINESS_MODES`에 속하고 단어가 있는 최대 15개 시도의 점수와 단어 수를 평균합니다. 긴 무음 평균에서 직접 입력을 뺍니다. 모의시험 조건은 같은 `mockId`의 시도가 5개 이상이면 점수를 평균합니다. 홈의 학습용 IH 준비도는 스크립트 숙련도 30%, 최근 최대 10개 말하기 점수 50%, 주제 다양성 20%를 합칩니다. 현재 코드로 `rec_latest.wav`의 20ms PCM RMS를 다시 계산했을 때 말소리로 검출된 7.70초와 긴 무음 2회가 보관 기록과 일치했습니다. 같은 전사에 현재 로컬 규칙을 적용하면 23점이며, 로컬 입력에는 질문의 실제 문장이 없어 낭독을 판별할 수 없습니다. `rec.wav`는 16.38초로 시도 3과 길이가 같지만, 현재 검출값 1.54초·2회는 보관값 0초·0회와 다릅니다. 시도 3과 이 파일의 대응은 길이로 추정하며, 발화 여부와 검출값 차이의 원인은 독립 청취 없이 확정할 수 없습니다.

## 로컬 평가와 준비도 재현

`localControls`는 문항 유형과 전사를 고정하고 실제 `DiscourseAnalyzer`, `FeedbackComposer`, `ErrorCounts`를 실행합니다. E와 E-clean에는 같은 합성 음향 입력을 주었습니다. 다른 사례는 음향 지표가 없는 직접 입력으로 비교했습니다.

| 재현 절차 | 실제 결과 | 기대 결과와 차이 및 학습 영향 |
| --- | --- | --- |
| A/B를 같은 도서관 경험 문항에 평가합니다. | A 20단어·32점, B 116단어·88점입니다. B는 길이와 연결어를 칭찬받고 수정 사항이 없습니다. | 문항을 완수한 A보다 B에 56점이 더 부여됐습니다. 질문에 맞게 답하는 연습을 총점과 수정 제안으로 강화하지 못합니다. |
| C에 내용은 그대로 두고 연결 표현만 추가합니다. | C 0회·38점에서 C+ 5회·52점으로 올랐습니다. 연결이 부족하다는 교정도 사라졌습니다. 구조 항목에서 연결어가 12.5점을 더했습니다. | 도서관 문제와 해결은 두 답 모두 빠져 있습니다. 논리 관계를 새로 설명하지 않아도 표지를 채우면 개선으로 보입니다. |
| 과거 서사 D에 관련 없는 자전거 구매 계획을 붙입니다. | 55점에서 64점으로 올랐습니다. D에는 미래 표현이 없다는 교정이, D+에는 두 시간대를 썼다는 칭찬이 나옵니다. | D는 질문이 요구한 시간대를 유지했습니다. D+의 추가 문장은 과제 수행을 개선하지 않았습니다. |

## AI 요청과 응답 처리 재현

실제 합성 호출에는 보관 설정에서 확인한 `gemini-3.5-flash`와 기존 환경의 Gemini 키를 사용했습니다. 평가 코드 `GeminiAiCoach.evaluate`가 `Prompts.evalSystem`과 `Prompts.evalUser`를 사용해 REST `v1beta:generateContent`로 요청합니다. 평가 설정은 `temperature=0.4`, 최대 출력 8192토큰, `responseMimeType=application/json`입니다. 학습자 프로필은 앱 기본값(IM1, 다음 목표 IM2, 최종 목표 IH)입니다. 보관된 녹음과 전사는 이번 호출에 사용하지 않았습니다. 보관 설정에는 당시 AI 사용과 텍스트 전송, 녹음 전사와 음성 전송 동의가 설정되어 있었습니다. 클라우드 전사 요청 코드의 `temperature=0.0`과 원문 보존 프롬프트는 확인했으며, 동일 녹음에 대한 새 외부 전사 요청은 실행하지 않았습니다. [GeminiAiCoach](../app/src/main/java/com/opicih/coach/ai/GeminiAiCoach.kt) · [Prompts](../app/src/main/java/com/opicih/coach/ai/Prompts.kt) · [GeminiTranscriber](../app/src/main/java/com/opicih/coach/ai/CloudTranscriber.kt)

## 수정 우선순위와 회귀 검증

우선순위는 시험 준비 판단에 직접 영향을 주는 오류, 현재 답변의 개선 방향을 바꾸는 오류, 기록의 해석을 어렵게 하는 오류 순으로 정했습니다.

| 순위 | 수정할 규칙과 학습 영향 | 회귀 검증 |
| --- | --- | --- |
| P0 | **준비도에 쓸 근거를 명시합니다.** `TYPED`는 작성한 답변으로 기록하고 발화 점수·길이·무음 조건에는 포함하지 않습니다. 무음은 측정된 시도에만 계산합니다. 전사 실패와 녹음만 있는 시도는 텍스트 평가를 미측정으로 두고, 모의시험 완료와 평가 가능한 문항 수를 구별합니다. 평가 출처·캡처가 섞인 총점 평균은 응시일을 앞당기는 근거에서 분리합니다. 누락 자료가 낮은 능력이나 유창한 발화로 처리되는 일을 막습니다. | 직접 입력 세 건, 음향 지표 없는 LIVE_STT, 로컬/AI 혼합, 텍스트 없는 모의시험, 레거시 `metricsJson={}`, 정상 녹음과 측정된 무음 0회, `BLIND`의 제외를 검증합니다. 저장·재조회·홈·다음 OPIc 화면에서 같은 출처와 결측 상태를 확인합니다. |
| P0 | **Gemini 응답의 필수 항목과 값 범위를 검증합니다.** 전체 점수·평가 항목·피드백 구조가 없거나 서로 모순되면 성공한 AI 결과로 저장하지 않습니다. 로컬 폴백을 유지하고 실패 이유를 표시합니다. 부분 JSON이 점수 0이나 거짓 오류 0을 남길 수 있습니다. | `{}`, `score` 누락, 범위 밖 값, `tenseErrors > 0`인데 근거 누락, 정상 응답, HTTP 오류를 주입합니다. 오류 시 `feedbackSource=LOCAL`이며 UI와 저장 점수가 일치하는지 확인합니다. |
| P1 | **질문과 미션을 먼저 확인합니다.** `AnalysisInput`에 질문 텍스트와 실제 과업을 전달하고, 의미 판단을 제공할 수 없으면 적합성을 미평가로 표시합니다. 내용 점수를 길이·표지 개수로 대체하는 경로를 제거합니다. AI 프롬프트도 과업 수행, 근거 구절, 한 가지 재시도 과제를 우선합니다. 길게 빗나간 답을 강화하는 피드백을 줄일 수 있습니다. | A/B, D/D-Q, 질문을 그대로 읽은 합성 사례, H와 그 미션을 따르지 않은 대조 사례를 사용합니다. 적합성 오류는 첫 교정에 나타나야 하며, 질문을 바꾸었을 때 적합성이 달라져야 합니다. 오프라인에서 의미 평가가 없으면 미평가를 표시하는지 봅니다. |
| P1 | **연결과 시제를 과업에 맞게 판단합니다.** `futureCount == 0 && wordCount >= 40` 교정과 모의시험의 일괄 미래 부족 메시지를 제거합니다. 비교는 질문이 과거와 현재를 요구할 때만 그 전환을 확인합니다. 미션이 원래 질문 유형보다 우선합니다. 연결어 수의 가점과 개수 채우기 미션을 실제 원인·순서·대조를 설명하는 과제로 바꿉니다. | C/C+, D/D+, G, H를 고정합니다. D에 불필요한 미래 권고가 없고 D+와 C+의 형식만으로 평가가 오르지 않아야 합니다. 미래를 명시적으로 요구하는 질문과 미션에는 해당 피드백이 남아야 합니다. |
| P1 | **전사의 출처와 오류의 근거를 전달합니다.** `EvalInput`에 실제 캡처 상태를 전달하고, `TYPED`에 원문 전사 프롬프트를 쓰는 분기를 고칩니다. 태그에서 직접 읽은 사건과 AI가 추론한 사건을 별도로 유지합니다. 오류 키에 공통 분류를 적용하고 AI와 로컬 피드백을 합칠 때 상충하는 항목을 해소합니다. 출처별 오류 탐지 결과에는 근거 절을 붙입니다. | E/E-clean, 누락 태그, 허위로 더 큰 수를 주는 AI 응답, 자기 수정 이후의 절, C의 동일 오류에 대한 두 키, H의 AI·로컬 상충 항목을 사용합니다. 태그가 없거나 보정한 전사에서는 측정 가능 범위가 드러나야 하고, 태그 근거와 AI 추정치가 덮어써지지 않아야 합니다. |
| P2 | **시간대와 반복 탐지를 보완합니다.** 시제 규칙이 같은 이야기의 다음 문장까지 과거 맥락을 이어받도록 보완하고, 명시적 현재 전환과 직접 인용은 예외로 처리합니다. 인접 반복은 문장 경계를 고려하고 `I I`를 놓치지 않도록 합니다. 확인한 오류를 구절 단위로 제시합니다. | F/F+, `yesterday`가 있는 문장과 없는 후속 문장, `now`가 있는 시간 전환, 과거 이야기 안의 인용, E/E-clean의 실제 반복과 문장 경계 반복을 검증합니다. |

기존 IM2·IM3·IH의 길이/점수/모의시험 기준은 각각 `50/55/50`, `70/60/55`, `90/65/60`입니다. 표본 최소 3개, 무음 평균 1회, 연습량 10일 또는 150분 역시 앱의 학습 설계값입니다. 이번 자료로 새 합격선이나 점수 가중치를 정할 근거는 없습니다. 검증 시에는 질문 유형별로 확보한 원음과 대조 전사를 사용해 오류 검출의 정밀도·재현율, 같은 질문의 쌍별 순서 일치, 피드백 근거의 정확성을 사례 수와 함께 기록합니다. 같은 모델에 동일 입력을 세 번 보내는 것은 이번 점검에서 변동을 발견하기 위한 설계이며, 재현성 허용 한계나 등급 기준으로 쓰지 않습니다. 이슈 #41에서 학습 효과를 확인할 때 첫 답변, 피드백, 재답변의 구절을 맞대어 한 가지 변화가 실제로 일어났는지 봅니다. 같은 내용을 외워 고칠 수 있으므로 새 질문의 응답과 지연 재검사도 같은 기준으로 검토합니다. 재검사 간격은 #39에서 확인한 일정에 맞추고, 독립 검토자는 답변의 순서와 앱 점수를 가린 상태에서 가능한 한 같은 기준을 적용합니다.

## 재현 방법

저장소 루트에서 JDK 17과 Android SDK 36으로 다음 명령을 실행합니다. `EvaluationValidityProbeTest`는 현재 동작을 출력하며, 위의 회귀 검증 표는 수정 후 요구하는 동작을 제시합니다.

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests 'com.opicih.coach.EvaluationValidityProbeTest'
```

- `localControls`와 `captureAndReadiness`로 전사·점수·수정 사항·준비도 출력값을 비교합니다. `aiResponseFixtures`는 외부 연결 없이 응답 디코딩과 오류 집계를 재현합니다.
- 실제 자료의 로컬 재현에는 해당 파일을 읽을 수 있는 환경에서 `OPIC_EVAL_LOCAL_ARCHIVE`에 `dist`의 절대 경로를 설정하고 `replayPrivateArchive`를 실행합니다. SQLite는 읽기 전용으로 열리며 출력에는 전사나 녹음 내용이 포함되지 않습니다.
- 실제 AI는 기존 Gemini 키가 `GEMINI_API_KEY`에 설정된 환경에서 `OPIC_EVAL_GEMINI_MODEL`에 사용할 모델을 지정하고 `geminiSyntheticRepeats`를 실행합니다. `OPIC_EVAL_GEMINI_CASES`에 쉼표로 사례를 선택하고 `OPIC_EVAL_GEMINI_RUNS`로 반복 횟수를 지정할 수 있습니다. 선택을 생략하면 첫 회차에 전체 사례를, 이후 회차에 주요 비교 사례를 보냅니다. 외부 호출 입력은 테스트 코드의 합성 사례입니다.
- 실행 결과는 Gradle의 `test-results/testDebugUnitTest/TEST-com.opicih.coach.EvaluationValidityProbeTest.xml`에 남습니다. 이번 빌드에서는 설치된 Build Tools 36.0.0과 분리한 Gradle 빌드 경로를 임시 초기화 스크립트로 지정했습니다.

최종 디버그 빌드에 성공했습니다. 전체 JVM 테스트는 294개가 통과했습니다. 실제 Gemini를 호출하는 테스트 1개는 최종 전체 실행에서 제외했으며, 별도 실행의 결과를 위에 기록했습니다.
