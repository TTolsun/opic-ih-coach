# 홈에서 시작해 대본을 외우기까지

2026년 11월 23일, Android 16 에뮬레이터 `opic_verify`에서 기존 대본 26개와 일부 학습 기록이 있는 상태로 점검했다. 화면에 적힌 말과 버튼을 누른 결과가 일치하는지, 같은 자료나 행동을 두 곳에서 관리해야 하는지를 기준으로 삼았다.

## 0.6.1 후속 수정과 확인 결과

아래 검토표는 0.6.0의 재현 기록이다. 0.6.1에서 표에 적힌 문제 8건을 수정했다.

- 홈 복습은 개인 대본의 남은 복습 순서를 고정한다. 에뮬레이터에서 자유 발화를 먼저 사용한 뒤 복습을 시작해 Recent Trip, Memorable Experience, Travel Routine 순서로 답변을 제출하고 홈으로 돌아왔다. [실제 첫 복습 화면](screenshots/answer-practice/daily-script-review.png)
- 상세와 읽기 연습에서 영어 본문 바로 아래에 해당 한국어 번역을 표시한다. 비교 메뉴에는 본문이 있는 다른 버전만 보인다. 대본 검색에는 한국어 뜻도 포함된다. [스크립트 상세](screenshots/answer-practice/shared-study-text.png)
- 아침 루틴 첫 항목에서 시스템 뒤로가기로 홈에 복귀했다. 진행 중인 진단은 한 버튼으로 저장된 다음 문항을 열었다. 빈 텍스트의 분석 버튼은 비활성 상태였다.
- 시험 일정 카드는 한 번만 표시한다. 아침 알람을 끄고 켰을 때 꺼짐 안내와 예약 시각이 바뀌었다. 중단한 미니 시험은 7문항으로 다시 시작했고, 답변을 저장한 시험은 홈에서 해당 리포트로 바로 이동했다.
- 대본 질문 생성은 기기 코드에서 분리했다. 말하기 화면은 녹음 인터페이스를 주입받고 번역 저장소는 한국어 번역 인터페이스만 사용한다.

## 0.6.0에서 먼저 바꾼 홈

홈 본문의 **스크립트 열기**를 제거했다. 전체 목록은 하단 **스크립트** 탭에서 한 번에 열린다. 홈의 첫 버튼은 **질문 듣고 답하기**다. **복습 예정 스크립트**의 개별 제목은 해당 대본을 바로 여는 지름길이므로 유지했다. [수정한 홈 화면](screenshots/answer-practice/home.png)

## 실제 조작에서 발견한 문제

| 우선순위 | 재현 방법과 결과 | 제안과 통과 기준 |
|---|---|---|
| 높음 | 말하기에서 **자유 발화**를 선택하고 홈 → 오늘의 훈련 → **복습 스크립트 말하기 3개**를 눌렀다. 이전의 자유 발화 화면이 복원됐고, 복습할 대본과 무관한 공원 비교 문제가 열렸다. | 오늘 복습할 대본과 연습 방식을 함께 넘긴다. 직전 모드가 무엇이든 첫 복습 대상이 열리고, 한 편을 마치면 다음 대상으로 넘어가야 한다. |
| 높음 | **아침 표현 루틴** 첫 항목에서 Android 뒤로가기를 세 번 눌러도 1/11에 머물렀다. 화면의 **나가기**는 홈으로 돌아갔다. | 첫 항목에서 시스템 뒤로가기는 나가기와 같은 동작을 해야 한다. 둘째 항목부터는 이전 표현으로 돌아가는 동작을 유지한다. |
| 중간 | 스크립트에서 **Favorite Destination → 다른 버전 보기 → 완성 대본 ✓**를 눌렀다. 같은 영어 본문과 듣기 버튼이 위아래로 반복됐다. 이 대본에서 Natural, Target, Short를 각각 골랐을 때는 내용이 없다는 안내가 나왔다. 상세 화면의 완성 대본 번역은 이 접힌 영역에 있다. | **외울 대본** 바로 밑에 한국어 뜻을 놓고, 비교할 다른 본문이나 검토할 제안이 있을 때만 버전 선택을 보여 준다. 현재 학습본은 한 번만 읽으면 되어야 한다. |
| 중간 | 진행 중인 **말하기 진단**에서 상단 **진단 이어서 하기**와 날짜 옆 **이어서 답하기**를 각각 눌렀다. 두 버튼 모두 같은 영어 질문과 같은 **2 / 5**에서 시작했다. | 진행 중인 진단에는 **2번째 문항부터 이어서 하기** 한 곳만 둔다. 완료된 진단에는 결과 보기를 유지한다. |
| 중간 | **직접 입력 → 분석**을 빈 채로 누르면 창이 닫히고 아무 결과도 나오지 않았다. 같은 창에 영어 답변을 입력하자 로컬 분석과 연습 기록이 생겼다. | 공백뿐인 동안 분석을 비활성화한다. 입력 후 분석을 눌렀을 때만 창이 닫혀야 한다. |
| 중간 | 설정에서 **매일 아침 알람** 스위치를 꺼도 바로 아래에 **다음 알람: 내일 07:00**이 표시됐다. 다시 켰을 때도 같은 문구였다. | 꺼진 상태에서는 **아침 알람 꺼짐**을 표시한다. 예약 시각은 켠 상태에서만 보여 준다. |
| 중간 | 미니 모의시험에서 답변 없이 종료하니 **저장된 답변이 없습니다**가 표시됐다. 홈에 생긴 **최근 모의시험** 카드의 결과 보기로 다시 들어가자 문항 수를 고르는 **시작** 화면이 열렸다. | 저장된 리포트가 있는 시험만 **결과 보기**로 연결한다. 답변 없이 중단한 시험에는 **다시 시작**처럼 실제 동작을 표시한다. |
| 낮음 | 홈 → **시험 관리와 추가 연습** 안에서 **접수 예정: SAIL**과 **시험 현황**을 각각 눌렀다. 둘 다 같은 **시험 일정** 화면을 열었다. | 가까운 시험 날짜와 **일정 보기**를 한 카드에 모은다. 기록 탭의 **다음 시험 추천**은 준비도와 응시 계획을 설명하므로 따로 둘 이유가 있다. |

복습 진입은 [오늘의 과제 생성](../app/src/main/java/com/opicih/coach/learning/PlanGenerator.kt)과 [홈 탐색](../app/src/main/java/com/opicih/coach/ui/AppNav.kt), 뒤로가기는 [아침 루틴](../app/src/main/java/com/opicih/coach/ui/screens/MorningScreen.kt), 본문과 번역 배치는 [스크립트 상세](../app/src/main/java/com/opicih/coach/ui/screens/ScriptsScreens.kt)에서 대조했다.

## 버튼별로 확인한 흐름

| 출발 화면 | 직접 눌러 본 항목 | 확인한 결과 |
|---|---|---|
| 홈 | 질문 듣고 답하기, 질문 듣기, 다시 듣기, 질문 보기, 내 이야기 힌트, 이 대본 외우기, 스크립트 선택 | 질문을 숨긴 상태로 시작하고 필요할 때만 질문과 힌트를 펼칠 수 있다. 암기로 이동하면 해당 대본을 읽을 수 있다. |
| 홈 | 측정 기준, 오늘의 훈련, 다음 · 아침 표현 루틴, 다시 말하기 | 기준 안내와 오늘의 과제가 열렸다. 다시 말하기는 이전 질문에 재도전하는 화면으로 이동했다. |
| 홈 복습 목록 | 나머지 더 보기, Domestic Travel · Travel Routine | 접힌 목록을 펼친 뒤 제목을 누르자 해당 대본 상세가 열렸다. 전체 목록 탭과 역할이 다르다. |
| 음성 답변 | 말하기 시작, 녹음 멈추고 분석 | 녹음 시간이 표시됐다. 무음으로 끝내자 인식된 영어가 없다는 안내와 다시 말하기·직접 입력 방법이 나타났다. |
| 아침 루틴 | 예문 보기, 듣기, 헷갈려요, 다음, 이전, 나가기 | 예문이 펼쳐지고 자기평가 후 2/11로 진행했다. **이전**은 1/11로, **나가기**는 홈으로 이동했다. |
| 스크립트 목록 | 가져오기, 파일 선택, 직접 작성, 문장 틀, 소리로 듣기 | 파일 선택기, 수동 입력 양식, 문장 틀 목록, 연속 재생은 서로 다른 기능이었다. 개인 대본을 바로 여는 것이 주목적이므로 관리 도구들을 목록 위에 모두 펼쳐 둘 필요는 작다. |
| 스크립트 검색 | 검색에 Osaka 입력, 검색된 대본 열기, 같은 이야기 질문 펼치기, 영어 질문 선택 | Neighboring Countries 대본에서 중국과 일본을 설명하는 연관 질문을 골라 답변 연습으로 이동했다. 검색 코드는 영어 본문을 검사하지만 한국어 번역은 검사하지 않는다. 오사카처럼 한국어로 기억하는 장면도 검색 대상으로 삼을 만하다. |
| 가져오기·문장 틀 | 예시 영어 붙여넣기, 분석하기, 문장 틀, 틀 찾기, 승인 | 가져오기 미리보기에서 스크립트 한 편이 인식됐다. 문장 틀을 하나 승인하자 승인 대기가 15개에서 14개로 줄었다. |
| 스크립트 상세 | 대본 듣기, 다른 버전 보기, Original, Natural, Target, Short, Keywords, 완성 대본 | 원문과 학습본을 비교할 수 있다. 빈 버전과 현재 학습본까지 노출되는 문제는 위에 기록했다. |
| 스크립트 관리 | 편집, 삭제, 취소 | 편집 대상이 완성 대본이라고 표시됐다. 삭제 확인 창은 해당 제목과 삭제 범위를 알려 줬고 취소하면 상세로 돌아갔다. |
| 연속 듣기 | 재생, 일시정지, 다음, 종료 | 재생 상태와 선택한 대본이 바뀌었다. 한국어 번역 준비 상태는 **26 / 26**으로 표시됐다. 한 편의 대본 듣기와 여러 편을 이어 듣는 기능은 구분할 만하다. |
| 말하기 → 암기 | 듣고 읽기, 따라 말하기, 다음 문장, 이전 문장, 빈칸 채우기, 키워드 말하기 | 같은 연습 대본을 전체 본문, 한 문장, 빈칸, 키워드로 바꿔 연습했다. 암기 단계 안에서 선택하는 구성이 이해하기 쉽다. |
| 말하기 → 인출·응용 | 안 보고 말하기, 바뀐 질문, 응용 미션, 자유 발화, 틀 붙이기, 문단 사다리 | 방식별 질문과 힌트가 달라졌다. **문단 사다리**는 한 문장 답변으로 시작했다. **틀 붙이기**에서는 승인한 틀이 없어 별도 준비가 필요하다는 안내가 나왔다. |
| 말하기 진단·호텔 예약 롤플레이 | 진단 이어서 하기, 질문 듣기, 진단 목록, 이어서 답하기, 호텔 예약 롤플레이, 결과 보기, 새 세트 시작 | 진단은 저장한 문항으로 돌아갔다. 호텔은 완료한 3단계 결과와 새 호텔 문의 상황을 각각 열었다. |
| 오프라인 코치 | 돌발 질문 하나 내줘, 내가 반복해서 틀리는 문법이 뭐야, 내 취약 주제가 뭐야 | 질문 은행에서 뽑은 질문, 반복한 오류, 취약 주제 목록이 차례로 나왔다. 세 버튼은 서로 다른 결과를 준다. |
| 모의시험 | 12문항, 15문항, 미니 7문항, 시작, 질문 보기, 건너뛰기, 종료하고 리포트 보기, 계속 답변, 종료 재확인 | 문항 수를 바꾼 뒤 미니 시험을 시작했다. 건너뛰면 2번 문항으로 이동했다. 종료 확인에서 계속 답변을 고르면 2번을 유지했고, 종료를 확정하자 리포트가 열렸다. |
| 기록·시험 | 기록 삭제, 취소, 다음 시험 추천, 일정 보기, 시험 추가, 닫기 | 연습 기록 삭제 전에는 대상과 영향을 보여 줬다. 시험 추천에서 일정으로 이동해 새 시험 입력 양식을 열고 저장 없이 닫았다. |
| 설정 | 학습량, 재응시 규칙, Background Survey 주제, 아침 알람, 학습 블록 알람, 음성, AI · Gemini, 데이터 | 접거나 펼쳐 각 설정을 확인했다. 아침 알람은 실제로 껐다 켜서 안내 문구도 비교했다. |
| 설정 → 데이터 | 백업, 복원, 녹음 전체 삭제, 모든 학습 데이터 삭제 | 백업과 복원은 각각 시스템 파일 선택기를 열었다. 두 삭제 버튼은 확인 창을 열었고, 취소할 수 있었다. |

## SOLID를 코드에 대조한 결과

| 원칙 | 코드에서 확인한 근거 | 판단 |
|---|---|---|
| S · 단일 책임 | [SpeakingViewModel](../app/src/main/java/com/opicih/coach/ui/screens/SpeakingViewModel.kt)이 질문 선택, 마이크 수명 주기, 전사·분석, 재연습을 함께 조정한다. | 복습 문제를 고치려 해도 화면 상태와 기기 의존성까지 다뤄야 한다. 첫 분리 대상은 **어떤 대본과 질문으로 시작할지 결정하는 코드**다. |
| O · 개방·폐쇄 | [PracticeModeUi](../app/src/main/java/com/opicih/coach/ui/screens/PracticeModeUi.kt)에 이름·단계·힌트가 모여 있다. 실제 진입은 [AppNav](../app/src/main/java/com/opicih/coach/ui/AppNav.kt), 질문 선택은 SpeakingViewModel에서도 모드별로 분기한다. | 표시 정보는 확장하기 쉽다. 연습 방식을 추가할 때는 진입 대상과 필요한 대본을 명시하고, 메뉴에 넣었지만 엉뚱한 화면이 열리는 경우를 테스트해야 한다. |
| L · 리스코프 치환 | [AiCoach](../app/src/main/java/com/opicih/coach/ai/AiCoach.kt)의 번역 계약은 같은 순서의 번역 목록 또는 실패를 반환한다. 오프라인 구현의 번역 실패는 명시된 동작이다. | 이 차이만으로 치환 원칙을 위반했다고 볼 근거는 없다. 실제 번역을 지원하는 구현끼리는 결과의 개수와 순서를 동일하게 보장하는지 검증할 수 있다. |
| I · 인터페이스 분리 | [SegmentRepository](../app/src/main/java/com/opicih/coach/data/repo/SegmentRepository.kt)는 번역만 쓰는데, 스크립트 개선·평가·대화·후속 질문·요약·번역이 모두 있는 AiCoach를 받는다. | 번역 호출부가 필요로 하는 작은 인터페이스를 분리할 근거가 있다. 로컬 번역 테스트에서 대화와 평가까지 흉내 낼 필요가 없어진다. |
| D · 의존성 역전 | [ListenPlayer](../app/src/main/java/com/opicih/coach/playback/ListenPlayer.kt)는 음성 출력을 ListenSpeaker로 받아 [가짜 음성 출력으로 테스트](../app/src/test/java/com/opicih/coach/ListenPlayerTest.kt)한다. SpeakingViewModel은 앱 컨테이너를 꺼내 구체적인 AnswerCapture를 직접 만든다. | 연속 듣기의 분리 방식을 녹음에도 적용할 만하다. 그러면 실제 마이크 없이도 녹음 중 화면 이탈과 실패 후 재시도를 검증할 수 있다. |

## 검증 범위

화면 전환과 상태 표시는 에뮬레이터에서 확인했다. 대본 상세의 버전 비교는 대표 대본으로 점검했다. 백업·복원과 영구 삭제는 선택기 또는 확인 창까지 점검했다. 실제 발음 인식 품질, 알람의 실시간 수신, 유료 Gemini 응답, 모든 기출·시험 상태별 조건부 버튼은 이번 점검 범위에 포함하지 않았다.
