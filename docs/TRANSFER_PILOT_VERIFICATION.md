# 이슈 #47 파일럿 검증 기록

[실행 안내](TRANSFER_PILOT.md)에서 질문 제시, 시간표, 관찰 기준과 기록 양식을 확인할 수 있습니다. 평가 문항은 진행자만 보관합니다.

## 검증 결과

기준 커밋 `78a938c`의 별도 소스 사본에서 빌드한 0.4.1 debug APK를 Android 16(API 36) `opic_verify`에 설치했습니다. 기존 `opic_verify`의 설정을 복제하고 사용자 데이터가 없는 별도 인스턴스 `emulator-5556`에서 실행했습니다. 합성 직접 입력과 무음 마이크 동작으로 화면과 저장을 확인했습니다.

| 검증 항목 | 실제 관찰 |
| --- | --- |
| 지정한 H-P1 원문 | **인출 → 안 보고 말하기**에서 비교 스크립트를 선택했습니다. **질문 보기**를 누르기 전 질문 글과 답변·힌트는 숨겨졌습니다. 질문 글을 열어 내장 원문과 일치함을 확인했습니다. 합성 입력을 제출하니 결과에 스크립트 일부가 나타났습니다. **같은 질문 다시 말하기**를 누르자 마이크가 시작되고 결과·스크립트·질문 글이 다시 가려졌습니다. |
| 자유 발화와 재답변 | **응용 → 자유 발화**에서 나온 동네 묘사 문항을 사용했습니다. 첫 직접 입력을 저장한 뒤 **같은 질문 다시 말하기**를 눌렀습니다. 지난 답변과 힌트가 보이지 않았고, 마이크를 켰다가 입력 없이 종료하면 직접 입력 안내로 돌아왔습니다. 두 번째 합성 답을 입력하니 같은 질문의 새 결과가 표시됐습니다. 비교 줄에는 단어 수 차이만 나왔습니다. |
| 다른 주제의 같은 유형 | **같은 유형 새 질문**을 눌러 `Home & Furniture / 묘사`에서 `Movies / 묘사`로 이동했습니다. 질문 글은 다시 숨겨졌습니다. 열어 보니 좋아하는 영화 종류를 묻는 기존 은행 문항이었습니다. 이 동네·영화 문항은 화면 검증에 사용했습니다. |
| 예약과 재검사 | 동네 질문의 두 번째 자유 발화 결과에서 예약하자 **다시 말하기 예정 · 11/16**이 표시됐습니다. 11/13 KST의 홈에 기한이 된 항목이 없음을 확인했습니다. 별도 인스턴스의 자동 시각을 끄고 `adb shell cmd alarm set-time`으로 사흘 앞당긴 뒤 앱을 다시 열자 홈에 **다시 말할 질문이 있습니다**가 나왔습니다. **다시 말하기**에서 질문과 지난 답변·힌트가 가려져 있었습니다. **질문 보기**를 누른 뒤 동네 질문 원문이 이전과 글자 단위로 일치함을 확인했습니다. 합성 직접 입력을 제출하니 홈의 기한 표시가 사라졌습니다. |
| 저장과 기록 | **기록**에서 4회와 자유 발화 비율 75%를 확인했습니다. **최근 연습 기록**에는 집·가구 `Blind` 1건과 동네 묘사 `자유 발화` 3건이 표시됐습니다. 연습일의 두 시도와 시각을 이동한 사흘 뒤 재검사 시도는 별도 행이었고, 세 행의 모드 표시는 모두 같았습니다. 기한은 KST 기준이며 이 인스턴스의 기록 화면은 UTC로 표시했습니다. 무음 마이크 동작은 저장 건수에 들어가지 않았습니다. |

재현할 때는 위와 같은 순서로 H-P1과 자유 발화 시도 하나를 확인합니다. 자유 발화는 처음 표시된 검증용 은행 문항의 원문과 유형을 기록한 뒤 그 원문으로 재답변·예약·재진입을 비교합니다. 고정 평가 문항의 선택은 아래 수동 절차를 따릅니다. 시각 변경은 별도 검증 인스턴스에만 적용합니다.

### 검증 상태

- **설계·콘텐츠 검토 완료.** 스크립트 23개와 질문 은행 81개를 집계했습니다. H-P1 원문 일치와 즉시·지연 평가 문항 4개의 ID·정규화 원문 중복 여부를 검사했습니다. 14일 계획과 연습 문항까지 의미상 가까운 사례를 검토했습니다. 학습자 개인의 실제 노출과 소재 친숙도는 첫 시행 때 확인합니다.
- **앱 기능 검증 완료.** Android 16에서 원문 선택, 숨김, 재답변, 같은 유형 이동, 예약 및 재검사 완료와 기록을 확인했습니다. 기준 커밋에서 `.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest --offline`은 성공했습니다. JVM 테스트는 316개 통과했고 비공개 자료 재생과 Gemini 합성 반복 호출에 해당하는 2개는 건너뛰었습니다. 마이크 시작·정지와 빈 입력 안내를 확인했으며, 실제 발화 인식·청취 품질은 이번 검증에서 측정하지 않았습니다.
- **실제 학습 효과 미관찰.** 이 파일럿의 단계에 맞는 실제 발화는 확보하지 못했습니다. 직접 입력은 합성 자료입니다. 에뮬레이터의 날짜 이동은 예약 동작만 검증했습니다. 참가자가 사용할 소재가 있는지, 조건을 고정해 첫 녹음 6건씩을 확보할 수 있는지 실제 시행에서 확인합니다.

## 내장 개선안 적용 확인

집·가구 다섯 문항과 해외여행 두 문항에 `Target`, `Short`, `Keywords` 개선안을 제공합니다. `Recent Trip`과 `Comparison (Past vs. Present)`의 `Target`에는 질문에 맞춰 덧붙일 장면이나 설명을 추가했습니다. **스크립트 → 해당 문항 → 승인 대기 개선안**에서 선택한 개선안을 승인하면 학습본으로 적용됩니다. 기존 질문 원문과 개인 경험 원문을 보존합니다.

별도 Android 16 `opic_verify`에서 이전에 승인한 57단어 `Recent Trip` Target과 합성 연습 기록 1건이 든 버전 6 백업을 복원했습니다. 앱을 다시 열지 않아도 새 내장 개선안 3개가 나타났고, 이전 Target은 숙련도와 함께 활성 상태를 유지했습니다. 새 Target을 승인하자 보강한 답변이 활성 학습본으로 표시됐습니다. [새 Target 화면](screenshots/issue-47/recent-trip-target.png)

## 앱의 실행 범위와 수동 절차

| 파일럿 단계 | 현재 동작 | 수동 실행 방법 |
| --- | --- | --- |
| H-P1 기준선과 동일 문항 재답변 | **말하기 → 인출 → 안 보고 말하기 → 스크립트 선택 → Home & Furniture · Comparison (Past vs. Present)**에서 원문을 지정할 수 있습니다. **같은 질문 다시 말하기**는 마이크를 시작합니다. `BLIND` 결과는 스크립트 기반 암기 점수와 기존 답변의 일부 문구를 표시할 수 있습니다. | 진행자가 녹음 전 결과 화면을 가립니다. 같은 캡처 조건이 필요하거나 스크립트 노출을 관리하기 어려우면 진행자가 원문을 읽고 별도 로컬 녹음기를 사용합니다. 교정 시간에는 한 구절만 확인합니다. |
| T-P1, H-P2a/H-P2b, T-P2 및 평가 전용 문항 | 지정한 원문을 자유 발화에 직접 입력하거나 문항 ID로 열 수 있는 화면이 없습니다. **직접 입력**은 답변을 입력하는 기능입니다. **바뀐 질문**과 **응용 미션**은 스크립트에 연결한 표현 변형과 미션을 사용합니다. | 진행자가 현재 질문 카드 한 장의 원문만 읽습니다. 한 번 들은 뒤 10초를 재고, 최대 60초 동안 로컬로 녹음합니다. 계획한 질문을 열기 위해 **다음 질문**을 반복해서 누르는 절차는 사용하지 않습니다. |
| 다른 주제에서 같은 기능 확인 | **같은 유형 새 질문**은 같은 단일 유형, 다른 주제, 답한 원문의 정규화 중복 제외를 적용한 뒤 후보 중 하나를 고릅니다. 질문을 보기만 한 이력과 과업 수·의미상 중복·친숙도는 확인하지 않습니다. | 즉시·지연 적용에는 진행자가 보관한 질문을 사용합니다. 앱 기능을 확인할 때만 별도 합성 세션에서 추천 버튼을 사용합니다. |
| D+3 연습 원문 | 자유 발화의 완료한 답변에서 **3일 뒤 다시 말하기**로 예약하면, 홈의 **다시 말하기**에서 기한이 된 원문을 엽니다. H-P1의 `BLIND` 진입과 외부 녹음은 자유 발화 예약을 만들 수 없습니다. | 원문을 저장하고 달력에 날짜만 적습니다. D+3에 미연습 질문을 먼저 녹음한 뒤, H-P1의 스크립트를 다시 선택하거나 외부에 보관한 연습 원문을 같은 제시 방식으로 녹음합니다. 외부 녹음을 사용한 트랙은 재검사에도 외부 녹음을 사용합니다. |
| 시도 기록 | 최근 기록은 모드·주제·답변 요약을 표시합니다. 연습일과 재검사일의 시도가 각각 저장됩니다. 파일럿 단계와 힌트, 사전 노출은 기록 화면에서 구분할 수 없습니다. | 질문 ID·단계·시도 일시와 녹음 위치를 기록 양식에 적습니다. 결과 화면이나 기록을 열어 이전 전사를 비교하는 일은 두 지연 답변을 마친 뒤에 합니다. |

`SpeakingViewModel`의 일반 자유 발화는 질문 은행에서 무작위로 고릅니다. 지연 진입은 기한이 된 시도의 질문 텍스트, 주제, 유형으로 새 `QuestionItem`을 만듭니다. `TransferQuestions`의 필터와 Room의 예약 기능은 아래 앱 점검에 재사용했습니다. ## 최소 변경안

| 우선순위 | 문제와 기대 동작 | 수용 조건과 기존 이슈 |
| --- | --- | --- |
| P1 | 진행자가 정한 질문 원문을 자유 발화로 바로 열 수 있도록, 해당 시도에 한해 원문·주제·유형을 받는 진입점을 추가합니다. 기존 `QuestionItem`, 자유 발화와 예약 경로를 사용합니다. 평가 문항은 실제 제시 시점에 진행자가 입력하며 일반 후보와 스크립트 목록에 등록하지 않습니다. | 하나의 지정 문항을 무작위 이동 없이 열고 원문이 재답변과 D+3 예약까지 그대로 이어집니다. 질문 글·지난 답변·문장 틀은 답하기 전 숨겨집니다. 이전에 넣은 지정 문항은 일반 자유 발화나 같은 유형 추천에 나타나지 않습니다. #41의 재답변과 원문 예약을 재사용합니다. [#41](https://github.com/TTolsun/opic-ih-coach/issues/41) |
| P2 | 여러 회차에서 시도를 찾기 어려울 경우, 진행자 지정 진입점에서 파일럿 ID·단계와 무힌트/도움 여부를 기록할 수 있게 합니다. 이번 회차에는 로컬 기록 양식을 씁니다. | 같은 원문의 기준선·재답변·연습 원문 재검사, 즉시·지연 미연습 시도를 ID와 단계로 구별합니다. 도움 수준을 확인할 수 있고, 미응답 일반 시도에는 필드를 요구하지 않습니다. 자동 기준별 진단 전체는 #26의 범위에 둡니다. [#26](https://github.com/TTolsun/opic-ih-coach/issues/26) |

개별 질문을 읽고 기록하는 수동 경로로 첫 회차를 진행할 수 있습니다. 이번 변경은 저장소 문서에 적용했습니다.
